# Omni request and job workflow

Use Python 3.10+, the suite's Pillow dependency for local images and FFprobe for source/output video verification. No Google SDK is needed. Export GEMINI_API_KEY using the repository README's external .env instructions. Install the full plugin: the producer's scripts/video_provider.py owns common transport, approval and output handling.

Copy [omni.example.json](../assets/omni.example.json), replace its fictional prompt and update costEstimate from current pricing before approval. Required fields are schemaVersion=1, id and prompt. Optional model, mode, aspectRatio, durationSeconds, resolution, delivery, store, background, stream and task choose the documented controls. costEstimate contains usd, source URL and checkedAt date and is required for paid submission. Unknown fields are rejected.

## Media roles

The optional media array accepts objects with type=image/video, role, and either path or uri. Local paths resolve relative to the config. mimeType is optional. URI inputs must be Gemini Files URIs; a URI video also declares durationSeconds measured from its source. The helper measures local video and validates duration before submission.

```json
{
  "media": [
    {"type":"image", "role":"first_frame", "path":"product.png"},
    {"type":"image", "role":"last_frame", "path":"closing.png"},
    {"type":"image", "role":"image_reference", "path":"style.png"}
  ]
}
```

Use mode=interpolate for this fragment. Other roles are video_source and video_reference. The script maps Image1/Image2 and Video1/Video2 independently, builds explicit source/reference tags and retains stable input order. Reference numbering starts at zero. A loop needs one first_frame; the script binds it to both endpoints. Text generation needs no media. Edit/extend/upscale uses one uploaded video_source or a prior interaction, with optional appearance references.

## Previous turns and extension

previousRun points to a completed local Omni run and verifies its stored interaction context. Alternatively supply previousInteractionId directly; extension also needs sourceDurationSeconds when it cannot be read from previousRun or a source video's metadata. Never chain from a prior turn created with store=false. Each turn is a separately approved paid request. Download earlier output before provider expiration.

Extension adds the requested continuation to the expected source duration, bounded at 40 seconds. Review actual returned runtime; a provider may return a continuation rather than a joined file. The producer uses measured footage and correct source offsets, not the requested target alone. Upscale defaults to the measured source duration, requires a 3..10s source and 1080p/4k output, and does not invent higher native detail.

## Approval and execution

```sh
OMNI_TOOL="$SUITE/marketing-omni-video/scripts/omni_video.py"
python3 "$OMNI_TOOL" submit omni.json --out /path/to/work/omni-v1 --dry-run
# After explicit approval of this request and current estimate:
python3 "$OMNI_TOOL" submit omni.json --out /path/to/work/omni-v1 --approve-request SHA_FROM_DRY_RUN --approval-note 'User approved this Omni request in chat'
python3 "$OMNI_TOOL" status /path/to/work/omni-v1
python3 "$OMNI_TOOL" download /path/to/work/omni-v1
```

Dry-run performs local validation only, without a key/network or output files. Show the user the exact media/prompt/settings and estimate. Approval notes record real human authorization; they are not a way to bypass consent. Changed prompt, inputs, quote or settings changes the fingerprint. General ad-production permission does not enable paid generation, revisions or retries.

Default store=true preserves conversational context. background=true requires store=true; status makes one query and returns. stream=true requests SSE, checkpoints interaction identity and complete generated media steps, and supports later retrieval after interruption when stored. With store=false, later GET/chaining is unavailable: download from the saved creation output. URI delivery is the default for larger output; it is not a new billable generation. The initial URI is preserved even if later GET returns base64 instead.

The state and assets manifests retain request/reference hashes, interaction ID, storage/execution choices, original creation URI, generated MP4 bytes, measured dimensions/runtime/FPS/audio and review findings. They omit user_input/thought steps and base64 source dumps. Downloads retain matching existing files; changed files are not overwritten. If FFprobe fails, generated bytes remain recoverable. Do not resubmit an unknown paid request; investigate its saved interaction ID.

When the user asks to cancel a running background interaction, run cancel RUN_DIR and inspect status; cancellation is best effort and does not imply a refund. Stateless or synchronous requests cannot be cancelled through this command.

## Files upload

```sh
python3 "$OMNI_TOOL" file-upload source.mp4 --out /path/to/work/upload-v1 --dry-run
python3 "$OMNI_TOOL" file-upload source.mp4 --out /path/to/work/upload-v1
python3 "$OMNI_TOOL" file-status /path/to/work/upload-v1
```

Upload only media authorized for disclosure to Google. Uploading itself does not generate video. The upload state retains name, URI, source hash/MIME/metadata and readiness; copy the URI and measured duration into a later video config. Pending files prevent paid generation. Local helper limits are 100 MiB per upload, under 20 MiB per inline request and 256 MiB per API/download response. These are local guardrails, not provider maximums. File retention and region/access rules follow the provider; the helper does not automatically delete remote files.
